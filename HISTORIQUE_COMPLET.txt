4. PHASE 4: DECOUVERTE DU BUG IS_CAUSAL (2-3 juillet 2026)
================================================================================

4.1 Observation suspecte
- Le 32M VariantB avait une loss de 3.5 (tres basse)
- Mais generait du charabia
- En general, loss 3.5 = bon modele
- Ici, loss basse = MAUVAIS modele

4.2 Diagnostic
- Le 32M VariantB utilisait torch.triu MANUEL dans l'attention
- Donc le 32M avait un vrai mask causal
- MAIS tous les autres modeles (train_fr_100m.py, train_50m_18pct.py, etc.) n'avaient PAS is_causal=True dans scaled_dot_product_attention
- Resultat: l'attention voyait les tokens FUTURS pendant l'entrainement
- C'est du data leakage = triche bidirectionnelle

4.3 Preuve du collapse
- Loss anormalement basse (1.66 pour l'ancien training)
- Generation: "professionnelle professionnelle professionnelle..." (48-62% repeat)
- Le model apprenait des raccourcis bidirectionnels
- Il ne savait PAS generer en mode autorgressif

4.4 Verification du 32M VariantB
- VariantB avait un torch.triu correct dans attention
- Donc VariantB n'etait PAS en train de tricher
- La loss 3.5 etait legitime
- MAIS la generation etait quand meme en collapse
- Conclusion: le 32M est trop petit pour apprendre le langage FR

4.5 Impact sur la litterature
- Ce bug n'avait pas ete signale dans les modeles oscillatoires
- C'est pourtant le bug le plus classique en NLP
- Tous les transformers modernes utilisent is_causal=True

8. LISTE DE TOUTES LES DECOUVERTES
================================================================================

D1: Le FR est plus facile a apprendre que l'EN pour les petits modeles
    (entropie 5 bits vs 10 bits, tokenizer 2x plus compact)

D2: Le bug is_causal est le bug le plus classique en NLP autorgressif
    (data leakage, loss anormalement basse, generation dechue)

D3: Le 32M est en collapse malgre une loss de 3.5
    (loss basse ne garantit PAS la generation)

D4: Le 100M est le premier modele qui genere du francais coherent
    (unique=90%, repeat=0%, phrases grammaticalement correctes)

D5: L'ecart 32M vs 100M est MASSIF
    (32M: 28% unique, 100M: 90% unique — meme prompt, meme temperature)

D6: Le loss n'est PAS un bon proxy de qualite generative
    (32M: loss 3.5, generation terrible; 100M: loss 5.45, generation correcte)

D7: La temperature ne sauve pas le 32M
    (test a 0.6/0.8/1.0/1.2, tous en collapse)

D8: Le cosine LR aide significativement
    (vs exponential: 99% du LR a step 10K vs 73%)

D9: Les oscillateurs n'apportent PAS d'avantage clair sur les transformers purs
    (test baseline EN: loss comparable)

D10: Le couplage K avec 0.1 fixe est probablement trop agressif
     (recommandation: le rendre appris et plus petit)

D11: Il manque un MLP/SwiGLU dans le bloc oscillator
     (non-linéarité feedforward indispensable)

D12: Le modele n'est PAS vraiment Kuramoto
     (c'est plus proche de LRU/Griffin/S4D)

D13: Les metriques de generation automatiques sont indispensables
     (unique ratio, bigram repeat, trigram repeat)

D14: Le seuil de capacite est reel
     (en dessous de ~50M params, collapse garanti sur FR)

D15: Le token special </s> ne doit PAS etre dans les prompts
     (c'est un signal de fin de sequence)

D16: Le </s> aggrave le collapse mais n'en est pas la cause
     (32M collapse meme sans </s> — le probleme est la capacite, pas le prompt)

9. LISTE DE TOUS LES ECHECS
================================================================================

E1: Tous les modeles EN (135m v1-v7, 50m, thin, 2x, deep) n'ont pas converge
    (loss stagne 6.5-7.5, pas de generation correcte)

E2: Le multimodal (image captioning) a echoue
    (trop complexe, abandon)

E3: Le training sans is_causal a cree des modeles en collapse
    (loss 1.66 = data leakage, pas de vrai apprentissage)

E4: Le 16L 100M FR a stagne a loss 7.56
    (trop de couches oscillatoires, gradients qui disparaissent)

E5: Le 32M en collapse malgre loss 3.5
    (espace d'état trop pauvre, attracteurs de faible dimension)

E6: Le Gen crash pendant le training
    (bfloat16 vs float32 mismatch)

E7: Les power cuts ont interrompu le training plusieurs fois
    (checkpoint resume fonctionne mais perturbation)

E8: La generation CPU est tres lente pour le 100M
    (~1s par token, ~7 min pour 120 tokens)

E9: La vitesse de training a ralenti de 6.5 a 4.9 st/s
    (plus de donnees en cache, overhead de computation)

E10: Le white paper original etait trop ambitieux
     (claims de novelty Kuramoto non soutenus)

E11: Les comparaisons FR/EN dans le paper etaient invalides
     (tokenizers et datasets differents)

E12: L'ancien training (is_causal=False) a perdu du temps
     (des dizaines d'heures d'entrainement gaspillees)

10. PHASE 7: TEST PROMPTS SANS TOKEN SPECIAL (5 juillet 2026)
================================================================================

10.1 Hypothese
- L'ancien code utilisait </s> (token fin de sequence) dans les prompts
- Hypothese: demander au modele de continuer APRES </s> pourrait causer des problemes
- Test: encoder les prompts SANS ajouter </s> manuellement

10.2 Test execute
- Script: test_32m_prompts.py
- 4 prompts testes sans </s>: "Il etait une fois", "La France est un pays", etc.
- Comparaison avec ancienne methode (avec </s>)

10.3 Resultats
SANS </s>:
- "Il etait une fois": unique=28%, repeat=40% — toujours collapse
- "La France est un pays": unique=45%, repeat=27% — toujours collapse
- "Bonjour, comment allez-vous": unique=30%, repeat=41% — toujours collapse
- "Le chat est assis sur le canape": unique=40%, repeat=27% — toujours collapse

AVEC </s> (ancienne methode):
- "Il etait une fois": unique=0%, repeat=100% — collapse total

10.4 Conclusion
- Le </s> AGRAVE le collapse (100% repeat vs 27-41%)
- MAIS le 32M collapse meme SANS </s>
- Le probleme du 32M n'est PAS le prompt
- C'est une question de CAPACITE: 19.7M params insuffisant pour le FR
- Le seuil critique de capacite est CONFIRME

10.5 Decouverte D16
- Le token </s> en fin de prompt destabilise la generation
- Mais meme sans ce token, le 32M ne genere pas correctement
- La cause fondamentale est la taille du modele, pas le format du prompt
